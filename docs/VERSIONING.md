# 版本管理与发布规范

> 本文件是念风 Chat 版本号、分支、预览/正式发布与 GitHub 仓库保留策略的单一事实来源。
> 发布脚本与安全扫描细节见 [`RELEASING.md`](./RELEASING.md)；版本语义以本文为准。

---

## 1. 版本号：`MAJOR.MINOR.PATCH`

采用 `MAJOR.MINOR.PATCH` 三段式版本号，Git tag 统一加 `v` 前缀。

| 段位 | 升级条件 | 例子 |
|---|---|---|
| **MAJOR** | 架构更换、开创性大型更新、破坏性变更，或需要单独划分一个时代的版本 | `v0.43.0 → v1.0.0` |
| **MINOR** | 新增一项或一组功能，并进入稳定版本 | `v1.0.0 → v1.1.0`；`v1.1.0 → v1.2.0` |
| **PATCH** | 不新增功能、不做中幅度修改：Bug 修复、优化、文案/构建/稳定性调整 | `v1.1.0 → v1.1.1` |

补充规则：

- 预览版使用 `-preview.N` 后缀，例如 `v1.2.0-preview.1`；同一轮预览多次构建时递增 `N`。
- 正式版不带预览后缀，例如 `v1.2.0`。
- 一个 `MINOR` 的正式版发布之后，它的 `PATCH` 修复仍沿用该 `MINOR` 分支，例如 `v1.2.1`、`v1.2.2`。
- **只有至少 `MINOR` 发生变化时，才建立新的版本分支**；`PATCH` 修复不新开版本分支。
- 版本号必须同步写入 `package.json` 与 `scripts/desktop-wrapper/Cargo.toml`；发布前由脚本校验一致。

## 2. 分支模型

| 分支 | 用途 | 规则 |
|---|---|---|
| `main` | 稳定发布线 | 只接收已经通过预览验证的提交；正式 tag 从 `main` 打出 |
| `preview` | 日常开发 / 集成分支 | 所有改动先进入这里；预览 tag 从 `preview` 打出 |
| `feature/<name>`、`fix/<name>` | 临时特性 / 修复分支 | 从 `preview` 拉出，完成后合回 `preview`，不直接合入 `main` |
| `release/vX.Y` | 某个 MINOR 的维护线 | 仅当 `MINOR` 升级时创建，用于该版本的预览、正式发布与后续 PATCH |
| `hotfix/<name>` | 紧急修复 | 仍先发 `-preview.N` 验证，确认后合入对应版本线并发布 `PATCH` |

标准流程：

1. **开发**：从 `preview` 或对应 `release/vX.Y` 拉临时分支，完成改动并自测。
2. **进入预览**：合回 `preview` / `release/vX.Y`，更新对应版本号与预览说明，打 `vX.Y.Z-preview.N` tag，构建三件套附件，发 GitHub pre-release。
3. **验证**：在预览版上确认功能、回归、数据兼容与发布包可用。
4. **晋升正式版**：确认无问题后，把已验证的预览提交并入 `main`，在 `main` 上打 `vX.Y.Z` 正式 tag，发正式 Release。
5. **仓库整理**：正式版发布后，清理已过期的预览 tag / Release；按第 4 节的保留策略维护 GitHub 仓库。

## 3. Release 说明内容规范

GitHub Release、README 更新说明和 `docs/releases/*` 只写用户能感知的内容：

- **写**：新增功能、行为变化、修复内容、优化点、升级/兼容注意事项、已知问题。
- **不写**：内部讨论、方案争论、实现细节、未确定的计划、开发过程中的自我说明。
- **不写**：“不是 xxx”“没有 xxx”“并非 xxx”“这里不是……”这类此地无银三百两的防御性表述。
- **不写**：对标/比较其它项目的临时结论，除非是正式兼容性说明。
- 描述功能时直接说明用户能做什么，不解释“我们为什么不做某件事”；内部方案保留在工作区文档或代码注释里。

---

## 4. GitHub 仓库保留策略

长期只保留必要版本，避免 tag / Release / 分支堆积：

- **分支**：长期保留 `main` 与 `preview`；旧的 `release/*` 和临时分支在下一轮稳定版发布后删除。
- **正式版本**：保留所有 MAJOR 里程碑，以及必要的 MINOR 最终版本（例如当前稳定版和上一个稳定版）。
- **PATCH 版本**：只保留当前/最近稳定线所需的最后一个补丁版；同一 MINOR 的中间补丁版、重复版本清理掉。
- **预览版本**：只保留当前尚未晋升的最新预览；某个预览对应的正式版发布后，该预览 tag / Release 删除。
- **非版本 tag**：临时测试、内部里程碑、人名/主题式 tag 一律不作为正式版本保留，发布完成后删除。
- **Release 资产**：只给保留的正式版本保留三件套资产；预览 Release 若不再保留则连同资产一起删除。

## 5. 版本号示例

| 从 | 到 | 原因 |
|---|---|---|
| `v1.1.9-preview.2` | `v1.1.9` | 预览验证通过，晋升当前 MINOR 的正式补丁版 |
| `v1.1.9` | `v1.1.10` | 同线 Bug 修复 / 优化，不新增功能 |
| `v1.1.10` | `v1.2.0` | 新增一项功能并进入稳定版 |
| `v1.2.x` | `v2.0.0` | 架构更换、开创性大型更新或破坏性变更 |
