# 念风 Chat v1.1.1

v1.1.0 之后的修复版本，集中修正 QQ 群 @ 触发与外部渠道敏感确认两个链路问题。

## QQ 群 @ 触发

- 群聊规则中的 `requireAt`（仅 @ 时回复）关闭后，@ 机器人的消息不再参与回复概率，而是稳定触发模型；
  普通消息仍按“回复概率”决定是否触发。
- 设置窗口把容易混淆的两个开关改为：“仅 @ 时回复”和“@ 触发也受白名单限制”，并修掉复选框的嵌套
  label 结构，避免点击时被浏览器双触发。
- NapCat 桥增强 @ 识别：消息事件缺少 `self_id` 时会回退到 `get_login_info` 的登录 QQ；同时解析
  `raw_message` 里的 CQ `at`，避免部分 NapCat 版本只带数组 / 只带 CQ 码时漏判。消息元数据新增
  `atUserIds`，便于在聊天记录里排查 @ 对象。

## 外部渠道敏感确认

- `chat-permissions` 创建 pending 时会固化来源会话的确认身份：网页端主人 ID、渠道侧配置的用户标识
  以及渠道信任名单；微信clawbot / NapCat / QQ 官方机器人的确认回复不会再被当成普通消息写进聊天记录。
- 外部渠道插件在触发模型轮次时带 `skipUserAppend=true`，`chat-permissions` 不再因为 payload 没有
  `senderId` 就自动“补批准”未授权渠道的 pending。
- NapCat 群聊 / 私聊与 QQ 官方机器人私聊的确认上下文补齐 `qq:` 前缀匹配；主人身份与信任成员都能按
  规则确认。
- 确认词支持去掉零宽字符、空白与句末标点后匹配“确认 / 确定 / 同意 / confirm”；其它内容仍视为拒绝。

## 测试

- 冒烟测试新增外部渠道（自定义微信身份）确认回归：确认会放行原操作且不会写进聊天记录。
- NapCat 群聊规则新增“关闭仅 @ 限制后 @ 仍然直接触发、普通消息仍按概率”断言。
- NapCat 桥新增缺少 `self_id`、只在 `raw_message` 带 CQ `at` 的回归断言。
