# 念风Chat v2.2.0-preview.3

本次预览主要围绕 QQ 官方机器人渠道的群聊补全、路由稳定性与渠道自检。

## QQ 官方机器人 · 群聊

- 支持 `GROUP_MESSAGE_CREATE` 全量群消息：群管理员开启「机器人可获取群内全部消息」后，未 @ 机器人的普通消息也会进入渠道聊天记录并参与群规则判断；@ 消息继续走 `GROUP_AT_MESSAGE_CREATE`。
- 群聊规则对齐 NapCat 口径：
  - 「仅 @ 时回复」：关闭后普通消息按概率触发；
  - 「被 @ 时必定回复」：默认开启，可关闭改为让 @ 也参与概率 / 白名单；
  - 支持黑名单、白名单、@ 白名单限制、概率白名单、上下文条数、未触发时静默写入。
- 「回复时引用触发消息」与「回复时艾特触发者」改为真正的独立开关，默认关闭；群回复默认走主动消息，不会强制引用，主动额度不可用时自动回退被动回复。
- 修复群消息的绑定同步与路由：
  - bridge 已路由到本渠道、但本机绑定列表未同步时，不再静默丢弃；
  - 同一会话只归属最后一个保存它的渠道，自动清理重复绑定；
  - 启动时清理后端已经不存在于前端的渠道配置，避免已删除渠道继续抢路由；
  - 全量事件正文解析失败时生成占位消息并记录 payload keys，不再无提示丢失。
- 渠道详情新增自检信息：后端连接、后端插件版本、最近事件、最近入站、路由冲突；发现会话里被其它渠道绑定的会话会标记「已绑定到其它渠道」，可一键「改绑到本渠道」。
- 新增「重连网关」按钮，群权限或连接状态变化后无需重启整个应用即可重新 Identify。
- 修复未绑定私聊提示文案中的项目名错误（念心Chat → 念风Chat）。

## 长期记忆与群聊开关

- 群聊逐渠道记忆总结改为「显式开启」：总开关打开后，只有单独开启的群聊渠道才会生成新概括；未显式开启的渠道默认不生成。
- 修复旧版逐渠道开关语义反向的问题：旧的 `groupSummaryDisabled=true`（曾禁用）会迁移为不开启，`groupSummaryDisabled=false`（曾显式允许）迁移为开启。
- 修复设置页写裸渠道 id、chat-store 使用带类型前缀 id 导致开关命不中的问题；前后端都按同一套规则兜底。
- 私聊 / 隐私渠道的总结不受群聊开关影响；已存记忆仍可正常检索。

## 插件管理与健康状态

- 新增「设置 → 插件启用」：以「角色 → 渠道」为粒度控制外部插件；新安装插件会弹一次「默认为全体角色启用 / 关闭」选择，之后可随时细调。
- 外部插件工具在未启用的角色 / 渠道里连工具定义都不会下发给模型，执行时也会被拒绝；GitHub 助手同时接入该范围。
- 清理插件页的「插槽拥挤」噪音提示，并对重复告警去重。
- 调整标红 / 标黄规则：
  - 模块导入失败、`apply` 抛错、缺少必须依赖等无法正常运行时标红，并跳过该插件加载，不影响其他插件；
  - 依赖版本不匹配等“可能还能跑但没按最佳组合来”的情况标黄，插件仍会加载。
- 按本次实际改动维护了内置插件版本号；关于页版本号与 `package.json` 同步，不再停留在旧的 `2.0.3`。

## 点歌台

- 修复 QQ 官方机器人语音发送成功后，工具结果缺少明确成功标记 / message id 时模型可能误判为“没有发出去”的问题；语音成功结果现在带 `success: true` 与明确的成功说明，并兼容 QQ 接口的多种 id 字段。

## 兼容性与升级说明

- 现有 QQ 官方机器人渠道会在启动时自动迁移群规则：引用 / 艾特回复默认关闭，@ 默认必定回复；之后可在渠道编辑中自行调整。
- 桌面版、Web 版与后端 bridge 需要一起更新；`bridge.mjs` 改动必须重启后端进程才会生效。

## preview.2 追加修复

- 长期记忆：群聊逐渠道开关改为「显式开启」，未单独开启的渠道默认不生成新概括；旧版 `groupSummaryDisabled` 配置会自动迁移，前后端判断保持一致。
- 插件管理：修复「插槽拥挤」噪音提示并去重；新增「设置 → 插件启用」按角色 / 渠道控制外部插件；新插件安装时弹一次默认策略选择。
- 插件健康状态：模块导入失败、`apply` 抛错、缺少必须依赖等无法运行的情况标红并跳过加载；依赖版本不匹配等改为标黄，插件仍按最佳努力加载。
- 内置插件按本次改动维护版本号；关于页版本号改为与 `package.json` / 运行时 `VERSION` 同步。

## preview.3 追加修复

- GitHub 助手渠道通知恢复为「只跟随渠道订阅」：在「设置 → 插件启用」里关闭某个角色 / 渠道，只会停用 GitHub 工具和链接预览，不再吞掉已经订阅渠道的 Push / Release 通知。
- GitHub 轮询网络失败后会更快重试（默认间隔内重试，最长 5 分钟），并在从网络错误恢复后给一个更大的补发窗口，避免断网期间推送的提交因为超过旧事件上限被静默跳过。
- GitHub 轮询恢复正常后会自动清掉插件页顶部的「最近错误」，不再一直显示已经恢复的历史报错。
- GitHub API 代理解析增加 `HTTPS_PROXY` / `HTTP_PROXY` 环境变量兜底；`fetch failed` 等网络错误会带上更具体的 cause 信息，便于定位是 DNS、连接被拒还是超时。
