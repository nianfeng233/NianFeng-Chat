# 念风 Chat v1.1.6

本版本集中修复运行日志体验与模型上下文失忆问题：日志页可按类型自由勾选并记住选择，刷新后能可靠跟进后端日志；外部渠道 / 重新生成轮次会把用户发言写进工具轨迹，旧轨迹也会自动补回对应用户消息。

## 修复与改进

### 上下文构建 / 失忆修复

- 修复 `skipUserAppend` 轮次（外部渠道消息、重新生成等）只记录 assistant.tool_calls + tool 结果、缺少 user wire 的问题：
  - 下一轮构建上下文时不再丢失“用户刚发的那条消息”；
  - 模型不会再看得到自己的上一条问题、却看不到用户的回答。
- `chat-store` 新增按轮次读取协议轨迹的 `transcriptTurns()`；`context-builder` 对旧版本升级上来的轨迹，会按每轮结束时间把对应的可见用户消息补回对应轮次。
- 渠道连续来信时，按当前正在处理的消息 ID 限定上下文范围，避免把尚未轮到的后续消息误当成当前消息。
- 旧轨迹中缺少结构化 message_id 的 user wire，也会按时间匹配避免重复补入。
- token 预算截断保持原有“从最新往旧整轮截断”策略；如模型上下文足够，可在「设置 → 通用 → 上下文 token 预算」中调高。

### 运行日志页

- 移除「设置 → 通用 → 开发者 → 调试日志」开关；控制台固定输出 info 及以上，debug 级别仍可在日志页按需查看。
- 日志级别由「信息及以上」下拉改为「错误 / 警告 / 信息 / 调试」复选框，可任意组合，默认只勾选「信息」。
- 勾选组合写入配置 `logs.levels`，重开页面、重启应用以及多端同步后都会保留。
- 侧栏已有独立日志入口，设置左侧导航不再重复显示「运行日志」。
- 成功 HTTP 访问日志（如 `HTTP POST /api/xxx → 200 · 3ms`）不再进入日志页；4xx / 5xx 访问失败仍保留为警告 / 错误。
- 日志内容更贴近模型实际工作：
  - 收到渠道消息时显示渠道名、发送者与消息内容；
  - 开始处理请求时显示来源渠道、发送者与消息预览；
  - 渠道外发显示目标渠道与实际发送内容。
- 刷新链路增强：
  - 后端 `/api/logs/runtime` 返回实例 ID，前端检测到后端重启 / 数据目录切换时强制全量重拉；
  - 增量 `after` 分页改为从旧到新返回，落后超过 limit 时继续追赶，不再跳行；
  - 手动刷新会重建日志视图并重新拉取完整日志；
  - SSE 断线用不带旧 Last-Event-ID 的新连接重连，后台标签页切回或窗口聚焦时自动补拉 / 全量重同步；
  - 日志请求增加 `cache: 'no-store'` 与时间戳参数，避免代理 / 浏览器缓存旧日志。
