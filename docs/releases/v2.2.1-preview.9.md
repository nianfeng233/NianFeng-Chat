# 念风Chat v2.2.1-preview.9

本版集中处理手机端设置与日志页、日志时序与完整性、聊天历史消息构建、长期记忆检索策略与向量检索超时问题。

## 手机端设置与日志页

- 修复手机端顶部设置按钮无响应的问题：顶栏齿轮与底部“设置”标签现在都能正常打开 / 关闭设置页。
- 手机端日志页改为与桌面端同一套数据、筛选和按钮，只调整布局：
  - 日志列表不再固定高度、不再只在内层小窗口滚动；
  - 整页由日志页自身滚动，外层可以正常滑动；
  - 自动到底、手动翻页与“有新日志”提示会识别真正的滚动宿主。
- 修复日志页被父面板裁切、内容显示不全的问题。

## 日志时序与完整性

- 前端日志页不再单独维护第二份日志，改为直接读取后端 `runtime.log`：
  - 历史全量拉取 `/api/logs/runtime`；
  - 专用 SSE 实时流；
  - 断线 / 代理异常时 3 秒轮询兜底。
- 页面按后端日志 `id` 顺序展示，与 CLI 终端刷出顺序一致，不再按各自时间戳二次排序。
- 前端插件日志默认按 `info` 级别回传后端，电脑端、手机端与 CLI 看到同一份日志。
- “收到消息 / 请求开始 / 回复”等关键日志立即回传，不再等待批量刷新，减少时序倒置。
- 聊天链路信息级日志补齐并统一标记：
  - `[收到消息]`：哪个渠道、谁、发了什么；
  - `[请求开始]`：开始处理请求的渠道、发送人与消息预览；
  - `[模型请求]` / `[模型响应]`：调用哪个模型、耗时、输出与工具数量；
  - `[工具调用]` / `[工具结果]`：调用了什么工具、参数摘要与结果摘要；
  - `[回复]`：chat_send / send_document 实际发送的回复内容预览；
  - `[本轮结束]`：总耗时与模型思考耗时。

## 消息构建与工具历史

- 历史里的 `chat_send` 回复改为：
  - `assistant.content` = 当时的消息原文；
  - `assistant.tool_calls` = 对应的 `chat_send` 调用；
  - 紧跟一条 `role=tool` 的 `chat_send` 结果。
- 同一轮工具调用仍然原样返回，保证本轮动作连贯。
- 构建下一轮历史时，`read_messages` / `search_memory` / 知识库 / 联网等中间工具结果不再回传模型，只静默保留在工具轨迹库中。
- 可见消息路径与协议轨迹路径统一使用同一套历史构建规则。

## 记忆检索策略

- 收窄 `search_memory` 的调用条件：
  - 仅当当前消息与当前聊天窗口之外的历史关联度超过 50% 时才调用；
  - 日常问候、寒暄、闲聊、当前话题追问、常识问答明确不调用。
- 在 system prompt 和工具说明中明确区分：
  - `search_memory`：过往聊天记忆；
  - `kb_search`：本地知识库；
  - `web_search` / `browser`：联网实时信息；
  - `read_messages`：聊天原文。

## 向量检索超时修复

- 修复长期记忆查询时同步给旧记录补向量，导致单次检索拖到 60 秒失败的问题。
- 查询向量化只提交当前 query，并增加短超时；超时立即降级 BM25，工具仍然返回成功。
- 旧记忆向量改为后台小批量静默补齐，不阻塞检索请求。
- 不再把上游 embedding 的原始错误透传给模型，后端日志中会记录真实原因。
