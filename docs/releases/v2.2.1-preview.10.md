# 念风Chat v2.2.1-preview.10

本版修复自动更新拉起的旧窗口在下一次更新时显示内存报错（Not enough memory resources are available to process this command.）的问题。

## 问题原因

- 更新助手重新拉起新版本时，原先使用 `cmd /c start "" 启动念风.cmd`。
- 这种启动方式会让批处理所在的 `cmd.exe` 以类似 `/K` 的方式停在提示符，旧窗口不会像手动双击那样在念风退出后自动关闭。
- 下一次更新时，这个旧自动窗口如果没被正确识别 / 关闭，更新助手继续替换 `启动念风.cmd`，旧 `cmd.exe` 就可能读到被替换的批处理，出现内存报错并卡在提示符。

## 修复内容

- 发布包生成的 `启动念风.cmd` / `启动念风-无浏览器.cmd` 增加更新助手专用退出逻辑：
  - 仅当由更新助手拉起（存在 `NIANFENG_UPDATE_HELPER` 环境变量）时，念风退出后直接关闭控制台；
  - 手动双击打开的窗口保持原有行为。
- 更新助手动态生成的兜底启动脚本同步增加相同逻辑。
- 更新助手与一键重启拉起可见窗口时，改用 `cmd /C` 方式启动新控制台，避免再留下停在提示符的旧窗口。
- 更新助手增加旧窗口命令行的兜底识别：
  - 即使旧自动窗口没有 `NIANFENG_LAUNCHER` 标记，只要能识别出命令行来自 `启动念风.cmd` / `start.cmd` / `serve.cmd`，也会在替换文件前关闭它；
  - 确实无法判断时，本次更新跳过替换启动脚本，避免旧 `cmd.exe` 读取被替换一半的批处理而报内存错误，下次更新或手动重启后会自然替换。

## 测试

- `test:update-helper` 新增自动拉起窗口防残留回归：8/8 通过。
- `npm run release:gate` 通过（含 `verify:production` 与全量 `npm test`）。
