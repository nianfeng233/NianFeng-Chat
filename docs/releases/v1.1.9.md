# 念风 Chat v1.1.9

本版本汇总了 preview 分支上的长期记忆库、聊天记录稳定性、会话容器修复与界面增强更新。
WebUI 与会话数据保持向后兼容，可直接覆盖升级。

## 长期记忆库

- **真正的角色级长期记忆**：按角色独立存储（`memory.db` / `memory.json`），每 N 轮完整对话
  生成一条短概括并保存原文快照；概括与聊天原文分离，检索时按需回捞。
- **混合检索**：支持「向量语义 + BM25 关键词 + 时间过滤」RRF 融合；向量模型在
  「设置 → 模型 → 记忆模型」中选择，维度可自动检测。未配置向量模型时自动降级为关键词检索。
- **群聊记忆窗口**：群聊不再按“凑够若干轮完整对话”硬凑概括，而是在每次模型轮结束后检查
  当前群聊上下文的 message_id：与已概括记录重复超过 `N-5` 条时跳过，重复不超过 `N-5`
  条时概括整个最近 N 条消息窗口。默认 N=20，即重复 >15 条不总结、≤15 条总结。
  该策略只在模型真正触发后运行，没有按消息条数独立触发的总结定时器。
- **概括说话人名称修复**：概括 prompt 中的 assistant 使用真实角色本名 `role_name`，
  user 使用消息自带的 `sender_name`；不再把应用名“念风”写死进概括 prompt，也不会把
  渠道名 / 应用名当成对话人物。修复了角色名与用户昵称都不是“念风”时，记忆概括里却出现
  “念风”的问题。
- **隐私隔离与基线**：隐私渠道单独 scope，不与其它渠道互读；升级后默认只统计基线之后的新轮次，
  不回填旧历史。
- **记忆与知识库视图**：侧栏独立全宽视图，记忆库标签页列出概括并展开查看原文快照；
  知识库标签页在安装 knowledge-base 扩展后可浏览全文、标签与历史版本。

## 会话与聊天记录

- 后端启动时自动合并历史竞态产生的同渠道重复会话容器，修复“渠道 0 条但旧记录在另一个
  `conv.id` 下”和群聊 / 私聊上下文串位。
- 会话列表默认只同步 compact 元数据；聊天记录首屏只拉最近 20 条，向上翻页 / 点击加载更早时
  再按 `beforeSeq` 拉取，聊天记录不再随会话列表一起传输出全部正文。
- `session-service` 合并后端全量与本地滚动缓存，避免本地截断缓存把后端完整历史顶掉。
- 群聊上下文按消息条数计算（`chat.groupMessages`，默认 20），避免把群消息错误推算成“轮”。

## 模型与渠道

- DeepSeek / OpenAI 兼容 / Anthropic / Gemini / Ollama 模型接入继续修复工具历史、
  `reasoning_content` 与参数降级。
- 模型页支持远端模型候选；长期记忆概括模型与向量模型可单独配置。
- NapCat / QQ 官方机器人 / 微信 clawbot 渠道继续修复图片、被动回复、入站队列与连接稳定性。

## 稳定性修复

- 修复渠道容器竞态与聊天记录分页乱序。
- 长期记忆去重、基线计数与向量补写更加稳健。
- 前端提示、日志与错误路径补齐 `chat:request-done`，避免渠道入站队列挂起。
