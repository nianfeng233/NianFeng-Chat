# 念风 Chat v1.1.5

本版本修复日志页刷新“看起来没效果”、把 Prompt 改成缓存友好的固定 system + 结构化 user 元数据，并明确限制 chat_send 的短消息用法。

## 修复与改进

### 日志页刷新 / 实时更新

- 之前日志列表每次重新渲染都会 `innerHTML` 重建：用户手动往上翻后，`autoScroll` 为 false，新日志虽然进来了但视图被重置到顶部，看起来像“刷新没效果”。
- 现在：
  - 重新渲染时保留用户手动滚动位置；
  - 未自动滚动且收到新日志时，显示「有新日志 N ↓」按钮，点击回到底部；
  - 「刷新」按钮会取消暂停、强制自动滚动，并明确回到底部；
  - 刷新结果会提示“新增 X 条”或“没有新日志”；接口不可用时提示失败原因，而不是只弹一句成功。
- 保留 SSE + 3 秒轮询兜底，手动刷新强制重新拉取后端全量日志。

### Prompt 缓存友好化

- system prompt 只保留固定内容：角色人格、工具使用规则、工具清单、当前渠道策略。
- 移除 system 里的动态「当前时间 / 当前渠道 / 角色标识」，避免精确到毫秒的时间戳每轮都改变前缀，导致 DeepSeek 等按前缀命中的上下文缓存每轮失效。
- 每条 user 消息统一使用结构化信封：
  - `content.trust=untrusted` + 正文；
  - `meta.time` / `meta.timestamp` / `meta.timezone`；
  - `meta.channel` / `meta.channel_name` / `meta.channel_group`；
  - `meta.role_id`、发送者、`message_id` 等。
- 历史消息的时间戳固定在各自 user 消息的 meta 里，前缀稳定、模型也能快速知道先前的对话发生在什么时候。

### chat_send 短消息规范

- `chat_send` 工具描述明确：`messages` 数组每一项是一条独立消息，多条短消息请拆成多项，不要把多句话用换行符拼成一条。
- 日常短聊天不需要句尾句号，更接近 QQ / 微信真人输入习惯。
- 大段说明、代码、文章，或内容里本来就有大段换行的，改用 `send_document`。
